# WHY THIS FILE EXISTS (#409). Making the audit order-aware turned the cutover
# window from "clean" into seven real violations. Every one of them is a merge
# that already happened and CANNOT be repaired: back-filling a verdict is the
# right thing to do afterwards and it is explicitly NOT a gate, which is the
# whole point of the ordering fix. Left alone, the scheduled Verdict Audit would
# be red forever — and a permanently red alarm is a disabled alarm, which is the
# failure mode this control was created to avoid.
#
# WHY NOT JUST MOVE --since FORWARD. Because that is amnesty by DATE: it hides
# every violation in the range, including ones nobody has looked at, and it hides
# the next one too if the range is ever widened. This file names each PR
# individually. A violation that is not listed here still turns the workflow red,
# in the same window, on the same run.
#
# RULES FOR ADDING A LINE — all three, or do not add it:
#   1. The merge has already happened and cannot be un-merged.
#   2. It is written up in a retrospective under docs/retrospectives/, named.
#   3. The line says WHICH shape it was and points at the write-up.
# An entry is NOT a way to merge something unreviewed and tidy up afterwards.
# The gate (.claude/hooks/pre-merge-gate.sh) is what prevents; this is a ledger
# of what already escaped, and it should stop growing.
#
# FORMAT: a line whose first field is the PR number. Blank lines and lines
# starting with '#' are ignored. Anything after the number is the reason.
# A missing or unreadable file is treated as EMPTY — the audit can only get
# redder, never greener, if this file disappears.
