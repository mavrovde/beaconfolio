## 6. The changes

Enforcement order: hook > skill > charter > CLAUDE.md > command.

### A. `pre-merge-gate.sh` judges the merge's OWN repository (hook — the rule-13 gate had a false-allow)

**Evidence.** From this checkout, before the fix:
`echo '{"tool_input":{"command":"gh pr merge 5 -R mavrovde/viafrei-bridge --merge"}}' | bash .claude/hooks/pre-merge-gate.sh`
denied on *"PR #5 has no posted review verdict"*. The gate had read **beaconfolio's** #5 (a closed
Dependabot PR), because every `gh pr view`/`gh issue view` it ran omitted the merge's `-R`. In the
other direction it **allows**: if the CWD's PR #N carries a covering APPROVE, an unreviewed #N in
the named repository merges. The bypass-trace comment had the same defect, which is why the
bypasses of #467 and #468 in `$HOME/.claude/merge-gate-bypass.log` left no comment on either PR.

**Change.** The gate resolves the repository in gh's own precedence, and one flag walker
(`pmg_flag`) models every spelling:

1. A pull URL. It beats `-R`, measured by #501's reviewer on gh 2.102.0.
2. `-R/--repo` at the `gh`, `pr` or `merge` level, in any pflag spelling: spaced, `=`, attached
   `-Rx`, or ending a short cluster such as `-dR x` or `-sdRx`.
3. `GH_REPO`, including when a `bash -c`/`eval` body inherits it.

The result is passed to all four `gh` reads and to the bypass comment. The walk continues past the
PR number, because `gh pr merge 284 -R x` puts the repository last.

Where the text cannot show which repository gh will use, the gate **fails closed**. That covers an
earlier `cd`, `pushd` or `(cd …)` (also inside `bash -c`), an exported or bare `GH_REPO`, and a
`GH_HOST=` prefix. Unless the merge names its own repository, the gate denies with "name the
repository with -R".

**How this got here.** The round-1 draft parsed only spaced and `=` forms on the merge segment and
let `-R` beat a URL. #501's review probed 20 spellings gh accepts, and the draft allowed 13. One of
them, `gh pr -R x merge N`, was not recognised as a merge at all, even against the same repository.
That draft committed exactly the class-F defect this document counts: it claimed coverage the
probe refuted. Lessons §86 now carries the method: enumerate the parser's spellings, not the one
that bit you.

**Proof.**
- **Cases.** One per probe spelling (all 20, plus seven more shapes) and positive controls.
  Against the round-1 hook, **17 fail**. After the fix, **162 passed, 0 failed**.
- **Contract.** 47 mutants: one per walker arm, precedence rule and taint source, plus the URL
  guard the review asked to pin. The measured result is in the PR body.
- **The 7 of 8 original assertions still fail against the pre-fix `origin/main` hook.**

### B. `pr-evidence-e2e.yml`: an unrelated label can no longer cancel the summoned browser run (workflow, root cause)

**Evidence.** #499 was opened with four labels, including `run-e2e`. Runs 39140308774, 39140309571,
39140309773 and 39140309855 were **cancelled** and 39140310249 **skipped**. The `run-e2e` run was
displaced before it started. GitHub keeps at most one *pending* run per concurrency group and
cancels the older pending one when a new run is queued, whatever `cancel-in-progress` says. The
workflow's guard protected only a *running* run. This is lessons §76's class recurring one tier
over.

**Change.** A `labeled` event for any label other than `run-e2e` gets a run-unique concurrency
group, so it cannot touch the summoned run. `actionlint` 1.7.12 is clean. The masking residual (a
skipped run still posts a check-run under the tier's name) cannot be fixed this way. The
`issue-workflow` skill now says to add `run-e2e` in its own command after creation, and §76 records
the recurrence.

**Proof, live, on this PR (#501).** The workflow file is in its own `paths:`, so this PR runs the
changed workflow. It was opened with `run-e2e` among five creation labels, the #499 shape. #500
had just merged, so the PR was `CONFLICTING` at creation, and **no `pull_request` workflow ran at
all**: no merge ref, no runs. That is v1.16.0's #463 shape, and it gave neither a pass nor a fail.
After the rebase, the burst was reproduced on the mergeable PR: three labels removed, then re-added
in one `gh pr edit` (`run-e2e`, `documentation`, `P2-medium`) at 17:39:08Z. Result: the two
unrelated-label runs (39150571169, 39150571185) **skipped in their own groups**, and the `run-e2e`
run **39150570917 survived** and concluded **success** at `6337f6d6`. It cancelled only the stale `synchronize` run 39150539467,
which is what `cancel-in-progress` is for. On #499, the same burst left zero surviving runs.

### C. Session-id guard: CHECK C in `scripts/check_no_pii.sh` (lint, pre-push)

**Evidence.** 21 commits in the window carry a `claude.ai/code/session_…` URL. The rule against it
(issue-flow rule 8, owner directive 2026-09-06) has existed for six weeks with no enforcement. The
tooling's own attribution template asks for the trailer, so the default behaviour is to violate it.

**Change.** CHECK C fails when a commit that no remote-tracking ref has yet (exactly what the next
push publishes) carries a `Claude-Session:` trailer or a real session URL. History that is already
public is out of scope, so the 21 do not block anyone. It runs in the always-on pre-push `pii` leg.
**In CI it is a no-op** (HEAD is already on a remote ref there), which the script header says.

**Proof.** Five cases (published history ignored; an unpublished trailer fails and is named; a URL
in a body fails; quoting the rule and `Co-Authored-By` pass). **Five mutants: 12 killed / 0
survived / 0 invalid** for the whole contract. The first run of that contract caught a fake-green
in the fixture itself. `skeleton()`'s global `d` overwrote the fixture's path under dynamic
scoping, so the "published history" case had no history, and the scope mutant **survived**. That
is why the fixture now asserts it has a published commit before any case uses it.

### Proposed, not changed here

1. **Ship or diff the compose file at rollout** (lessons §83). `Roll Out To Prod Host` runs
   `docker compose pull/up` against whatever `docker-compose.prod.yml` the host already has. So

   The cheapest step is a read-only one: `ssh prod cat …/docker-compose.prod.yml | diff -

3. **The edge session needs this repo's rules or its own copy of them.** Today it produces
